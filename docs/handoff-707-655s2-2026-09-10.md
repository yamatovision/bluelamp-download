## 3. 🚨 次に測る人への警告: **「日次が走れば差し替わる」と思うな。走らない。**

`build-release.yml` の `check` job は **`releases/tags/build-<installer main の sha7>` が既に在れば `build_needed=false`** を出して `build` job ごと skip する。

```
🔬 実測（2026-09-10）:
  installer main = abd434b（2026-09-02T12:23:23Z ＝ 8 日間動いていない）
  release build-abd434b = 既に存在
  ⇒ cron（06:17 JST）は skip する
```

**発火条件は 2 つだけ**:
1. **installer main に新しい commit が入る**（＝ sha7 が変わり、その release がまだ無い）
2. **`gh workflow run build-release.yml`（手動 dispatch）**——`workflow_dispatch` は**無条件で `build_needed=true`**

⇒ **dmg が `mac-abd434b` 由来へ差し替わるのは、次に上のどちらかが起きたとき。**
⛔ **これを「PR #6 が効いていない」と読まないこと。**指紋を短時間に二度変えないための判断（CTO 裁定 B・2026-09-10）であって、**設計どおりである**。

## 5. 判定の正しい撃ち方（⛔ ここを間違えると「直った」と誤読する）

🚨 **`releases/latest` の `tag_name` は判別子にならない。**
同じ installer commit を作り直すと**タグ名は前と同じ**（`build-<同じ sha7>`）になるため、**「新しく出た」と「古いまま」を区別できない**。

⭕ **正しい判別子**:
1. **アセットの `created_at` と本数** — `gh api repos/O/R/releases/latest --jq '.assets[]|{name,size,created_at,uploader:.uploader.login}'`
2. **指紋の照合** — 恒久 URL から実物を落として `shasum -a 256` を採り、`SHA256SUMS.txt` の値および**期待する出所（`mac-<sha7>` の SUMS）**と突き合わせる
3. **恒久 URL の HTTP コード** — 🔬 **陰性対照を必ず添える**（存在しない名前が 404 のままであること。計器が何でも 200 と言っていない証拠）

🚨 **run が全 step 緑でも、載ったものが正しいとは限らない。**2026-09-10 の取り違えは **run success・warning も正しく発火**した状態で起きており、**指紋を突き合わせて初めて分かった**。⛔ **緑と「正しいものが出た」は別。**

## 6. 2026-09-10 に直した式（PR #6・`513216f`）

**真因**: `gh release list --json createdAt` の **`createdAt` は「タグが指す commit の日時」**であって公開日時ではない。

```
🔬 実測:
  mac-abd434b  createdAt=2026-08-31T12:22:55Z  publishedAt=2026-09-10T08:54:51Z
  mac-0ae7e11  createdAt=2026-08-31T12:22:55Z  publishedAt=2026-08-31T12:28:07Z
  ⇒ 同じ commit を指す 2 つのタグは createdAt が同値になり、並べ替えが判別子にならない
  ⇒ sort_by(.createdAt)|reverse|.[0] が 9 日前のほうを選び、それが GA に載った
```

⚠️ **2 次被害のほうが重い**——同じ `createdAt` から出した「経過日数」を**鮮度ガードの入力**にしていたので、**成果物の年齢ではなく commit の年齢**を測っていた（1 時間前に作った dmg も「9 日前」と出る）。**上限 30 日の門は別の量を測っており、通ったのは偶然だった。**

**直したもの**:
- `createdAt` → **`publishedAt`**（**選別と鮮度計算の両方**。⛔ 片方だけ直すと別の量を測る計器が生き残る）
- **選別の判断を判定器へ**（`.github/scripts/select-mac-release.sh`・I-O を持たない）
  - `mac-<exe と同じ sha7>` が在ればそれ（理由 `same-sha7`）／無ければ経過日数が最小のもの（理由 `newest`）＋出所の食い違い warning
  - ⛔ **同一 sha7 を必須にはしない**（`release-macos.yml` は dispatch 専用で日次と歩調が合わず、必須にすると**日次がほぼ常に赤**になる＝誰も見なくなった赤が残る）
  - **経過日数が同値なら先着を保つ**（⛔「同値なら後勝ち」は、判別子でない並び順に結果を左右させる形＝**この事故そのもの**）
- workflow 側は**候補を全件と経過日数を測って渡すだけ**。並び順に意味を持たせない

**回帰の標本がテストに在る** — `.github/scripts/tests/select-mac-release.tests.sh` に、**今回の取り違えそのもの**（`createdAt` 同値・`publishedAt` 相違の 2 件）を**並び順を入れ替えた 2 本**で入れてある。
🔬 **旧実装（並び順の先頭を採る）を差し込むと `exit=1`・14 failed** ＝ 回帰が検出される。⛔ **この標本を消すと、次の席が同じ式に戻せてしまう。**
